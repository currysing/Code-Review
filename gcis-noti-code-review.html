CriticalF-01: Committed credentials or key material

Plain-English explanation. the project contains passwords, client secrets, access keys, private-key material, or certificate passwords in files that are part of the repository. Source-controlled secrets are not private. Anyone with a clone, backup, CI artifact, or leaked archive can read them. Even if a value is intended for development, teams often reuse it or accidentally deploy it.

How it surfaces in this project. The evidence below shows the concrete files and lines where this pattern appears.

  • gcis-noti/config/egis_email_prod.properties:5 KEY_STORE_PASSWORD=cGFzc3dvcmQ=
  • gcis-noti/config/egis_email_prod.properties:10 TRUST_STORE_PASSWORD=Y2hhbmdlaXQ=
  • gcis-noti/config/egis_email.properties:5 KEY_STORE_PASSWORD=UEBzc3cwcmQ=
  • gcis-noti/config/egis_email.properties:10 TRUST_STORE_PASSWORD=Y2hhbmdlaXQ=

Why it matters. Credentials or key material in source control should be treated as exposed. This can enable database, Redis, OAuth, certificate, or internal-service compromise if the repository or artifacts are shared.

Recommended fix. Rotate affected secrets, remove them from source control, and load values from environment variables, deployment secrets, or a vault. Add secret scanning to CI.

MediumF-02: Bundled binary/certificate artifacts

Plain-English explanation. the repository contains deployable binary files and certificate/key-store files. Reviewers cannot easily see what is inside a compiled JAR, and certificate stores can contain reusable private or trust material. These files should usually be built or injected during deployment rather than committed.

How it surfaces in this project. The evidence below shows the concrete files and lines where this pattern appears.

  • gcis-noti/egis-notification-1.0.0.jar:1 binary/certificate artifact committed
  • gcis-noti/cert/keystore_uat.p12:1 binary/certificate artifact committed
  • gcis-noti/cert/keystore_prod.p12:1 binary/certificate artifact committed
  • gcis-noti/cert/jssecacerts:1 binary/certificate artifact committed

Why it matters. Committed runtime binaries and certificate stores are difficult to review and can carry reusable key material.

Recommended fix. Build binaries in CI from source and inject cert/key material from deployment secrets.
