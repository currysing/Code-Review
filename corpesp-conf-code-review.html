CriticalF-02: JWT validation is disabled or claims are decoded without validation

Impact. Forged or expired tokens can be accepted or used for user context if code trusts unvalidated claims.

Evidence.

  • corpesp-conf/DPOCorpID.Core/Program.cs:63 ValidateIssuer = false,
  • corpesp-conf/DPOCorpID.Core/Program.cs:64 ValidateAudience = false,
  • corpesp-conf/DPOCorpID.Core/Program.cs:65 ValidateLifetime = false,
  • corpesp-conf/DPOCorpID.Core/Program.cs:66 ValidateIssuerSigningKey = false,
  • corpesp-conf/DPOCorpID.Core/Program.cs:67 RequireSignedTokens = false

Recommended fix. Require issuer, audience, lifetime, and signing-key validation outside local-only diagnostics. Do not drive authorization from ReadJwtToken-decoded claims.

HighF-03: Endpoints are explicitly anonymous

Impact. Anonymous controller actions are risky when they perform business, signing, onboarding, administration, callback, or proxy operations.

Evidence.

  • corpesp-conf/DPOCorpID.Core/Controllers/EspUserController.cs:75 [AllowAnonymous]
  • corpesp-conf/DPOCorpID.Core/Controllers/EspUserController.cs:200 [AllowAnonymous]

Recommended fix. Review every AllowAnonymous usage. Keep only health and externally required callbacks, and protect callbacks with mTLS/HMAC/replay controls.

Limitations

This was a first-pass static review. I did not run the service, verify deployed ingress controls, exercise endpoints, review every business rule, or perform dependency/CVE analysis. External gateway controls may reduce exposure but do not remove risks from committed secrets, disabled validation, or debug code in deployable projects.
