CriticalF-02: Controllers are mapped without visible authentication middleware

Impact. Business endpoints may be callable without identity checks if the service is reachable directly or through a misconfigured gateway.

Evidence.

  • intf-sbp/DPOCorpID.Core/Program.cs:48 app.MapControllers();

Recommended fix. Configure authentication and authorization in the service, add a fallback authorization policy, and explicitly mark only health or verified callback endpoints as anonymous.

HighF-03: Permissive CORS policy

Impact. Wildcard CORS increases browser-based attack surface around token-bearing or admin APIs.

Evidence.

  • intf-sbp/DPOCorpID.Core/Program.cs:46 app.UseCors("AllowAll");

Recommended fix. Restrict origins, methods, and headers to the actual portal/admin domains required by deployment.

HighF-05: Debug or test endpoints are present in deployable code

Impact. Debug endpoints can leak configuration, exercise privileged flows, or create test security material if deployed.

Evidence.

  • intf-sbp/DPOCorpID.Core/Controllers/AccountController.cs:13 public class AccountController(AccountService accountService, TestAccountService testAccountService) : BaseController
  • intf-sbp/DPOCorpID.Core/Controllers/InitController.cs:13 public class InitController(CorpIdService corpIdService, TestCorpIdService testCorpIdService) : BaseController

Recommended fix. Exclude debug controllers from non-local builds or gate them behind strong admin auth and environment checks.

Limitations

This was a first-pass static review. I did not run the service, verify deployed ingress controls, exercise endpoints, review every business rule, or perform dependency/CVE analysis. External gateway controls may reduce exposure but do not remove risks from committed secrets, disabled validation, or debug code in deployable projects.
