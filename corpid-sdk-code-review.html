CriticalF-01: JWT validation is disabled or claims are decoded without validation

Impact. Forged or expired tokens can be accepted or used for user context if code trusts unvalidated claims.

Evidence.

  • corpid-sdk/shared/Framework.Utils/Context/User/UserContextFetcher.cs:241 var jwt = handler.ReadJwtToken(token);
  • corpid-sdk/shared/Framework.Models/Options/AuthenticationOptions.cs:158 /// When true, user-context helpers may decode the Bearer JWT with ReadJwtToken (no signature or lifetime validation)
  • corpid-sdk/shared/Framework.Security/Utils/JwtTokenHelper.cs:22 var jsonToken = tokenHandler.ReadJwtToken(token);
  • corpid-sdk/shared/Framework.Security/Utils/JwtTokenHelper.cs:41 var jsonToken = tokenHandler.ReadJwtToken(token);
  • corpid-sdk/shared/Framework.Security/Utils/JwtTokenHelper.cs:60 var jsonToken = tokenHandler.ReadJwtToken(token);
  • corpid-sdk/shared/Framework.Security/Utils/JwtTokenHelper.cs:100 var jsonToken = tokenHandler.ReadJwtToken(token);

Recommended fix. Require issuer, audience, lifetime, and signing-key validation outside local-only diagnostics. Do not drive authorization from ReadJwtToken-decoded claims.
